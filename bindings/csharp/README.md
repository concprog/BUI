# BUI for C#

Blender's widgets, layout and interaction rules from .NET, in three layers:

| Layer | Assembly | What it is |
|---|---|---|
| Interop | `Bui` (`Bui.Interop.Native`) | Every `BK_*` function, struct and constant of `kit/include/BUI_kit.h`, generated by ClangSharp. Blittable signatures only (`[assembly: DisableRuntimeMarshalling]`), callbacks as `delegate* unmanaged`. |
| Components | `Bui` | `Node`, `Frame`, `Panel`, `Button`, `Label`, `Canvas`, `Context`, `Window`, `Raster`, `Kit`. |
| Forms | `Bui.Forms` | A Windows Forms-style API: `Form`, `Button`, `Controls.Add`, `Location`, `Size`, `Dock`, `Click`, `Application.Run`. |

Status: a first slice. Linux, macOS and Windows (MSVC or MinGW); CI builds and tests all four runners (Linux x64, macOS arm64 and x64, Windows x64).

## Install

```sh
dotnet add package BlenderUI          # components (and the kit for linux-x64, osx-arm64, osx-x64, win-x64)
dotnet add package BlenderUI.Forms    # the Windows Forms-style API
```

The package carries the kit as `runtimes/<rid>/native/` (`bui_kit.dll`, `libbui_kit.dylib`, `libbui_kit.so`); .NET copies the one for the app's platform.

## Build

The binding loads `libbui_kit` (a shared build of the kit) by the name `bui_kit`:

```sh
cmake -S . -B build -DBUI_BUILD_CSHARP_BINDINGS=ON
cmake --build build --config Release --target bui_kit_shared   # build/bindings/csharp/: libbui_kit.so, libbui_kit.dylib or bui_kit.dll
cd bindings/csharp
dotnet run --project tests/Bui.Tests              # headless suite
dotnet run --project examples/Hello               # a window
dotnet run --project examples/Widgets             # panels, fields, sliders, toggles, a progress bar
dotnet run -c Release --project bench/Cells -- --cells 3000 --mode anim   # the cells benchmark
```

The projects copy the library from `build/bindings/csharp`; pass `-p:BuiNativeDir=<dir>` for another build directory. The libraries target `net8.0`; the tests and example target `net9.0`.

## Use a local build in your app

Two procedures, both from the native build above. They work the same in Rider, Visual Studio and the `dotnet` command.

**Reference the project**, to change BUI and your app together. Add to your app's `.csproj`:

```xml
<ItemGroup>
  <ProjectReference Include="path/to/BUI/bindings/csharp/src/Bui.Forms/Bui.Forms.csproj" />
</ItemGroup>
```

`Bui.csproj` copies the native library from `build/bindings/csharp` into your app's output folder. For a different build folder, set `<BuiNativeDir>` in your app's `.csproj`.

**Install a local package**, to give an app a fixed build. Put each library in a folder with the name of its platform, then pack:

```sh
mkdir -p natives/linux-x64                          # osx-arm64, osx-x64, win-x64
cp build/bindings/csharp/libbui_kit.so natives/linux-x64/
dotnet pack bindings/csharp/src/Bui -c Release -p:BuiNatives=$PWD/natives -o feed
dotnet pack bindings/csharp/src/Bui.Forms -c Release -o feed
```

Add `feed` as a package source (Rider: **Settings → NuGet → Sources**; Visual Studio: **Tools → Options → NuGet Package Manager → Package Sources**), then install `BlenderUI.Forms`. NuGet caches each version: before you pack the same version again, delete `~/.nuget/packages/blenderui` and `~/.nuget/packages/blenderui.forms`.

The app must target `net8.0` or later and run as 64-bit. `DllNotFoundException: bui_kit` means the library is not in the output folder.

## Forms

```csharp
using System.Drawing;
using Bui.Forms;

using var form = new Form { Text = "Hello from C#", Size = new Size(320, 120) };
var button = new Button { Text = "Click me", Location = new Point(110, 40), Size = new Size(100, 24) };
button.Click += (_, _) => button.Text = "Clicked";
form.Controls.Add(button);
Application.Run(form);
```

- `Location` and `Size` place a control absolutely (the kit's place manager). `Dock` other than `None` packs it against a side of its container (`Fill` takes the rest).
- Only containers (`Form`) have `Controls`.
- `Form.Context` drives a form without a window: `Configure`, `Press`, `Release`, `Motion` (tests, other hosts).
- `Controls.Add` moves a control from another container, `Remove` leaves it usable, and `Dispose` removes it. The [Forms page](https://github.com/ppmpreetham/BUI/blob/main/website/src/content/docs/csharp/forms.mdx) lists every type and member, and how to measure test coverage.

## Components

```csharp
using Bui;

var root = new Frame();
var button = new Button("Press") { Geometry = GeometryManager.Pack };
button.Click += (_, _) => System.Console.WriteLine("pressed");
root.Add(button);

using var context = new Context(root);
using var window = new Window(context, "BUI", 320, 120);
window.Show();
Window.Run();
```

`Node` takes any kit type (`new Node("slider")`) and every property by name: `Set("max", 10)`, `Set("text", "…")`, `GetNumber`, `GetString`. An unknown type or property throws `ArgumentException`. `Node.Event` delivers every kit event (`NodeEvent`: `Kind`, `A`, `B` as `BUI_kit.h` documents them).

`Panel.Body` is where a panel's content goes (nodes added to the panel itself go in its header). A part the kit builds itself, like that body, gets a borrowed wrapper from `Child(i)`. `Context.Render(raster)` draws into a `Raster` without a window; `Raster.Pixels` reads the result.

## The cells benchmark

`bench/Cells` is `bindings/rust/bench` (bui-bench) from C#: the same 1000x800 window of N rounded, numbered cells, the same colours and labels, and the same measurement as `common/measure.rs` (3 s warm-up, a 10 s window of process CPU time over every thread, frames and resident memory, one JSON line). `--mode anim` changes every cell every frame, paced to vsync; `--mode one` only cell 0. The cells are canvas items, and a frame replaces the ones that changed: the labels are encoded once, so a frame allocates nothing in C#.

## Ownership and threads

- A `Node` owns its native node. A parent only holds it: while a parent holds a node, the node's wrapper stays alive (the kit's retain and release hooks), so handlers keep working without a reference of your own.
- `Dispose` removes a node from its parent and frees it. A detached node that is collected is freed on the UI thread at the next input call or loop iteration.
- The kit is a UI-thread API. Call everything, `Window.Quit` included, from the thread that runs `Window.Run`.
- An exception in a handler never crosses native frames: it is held and thrown from the input call that caused it, or from `Window.Run`, which then stops.

## Regenerate the interop layer

`src/Bui/Interop/Native.g.cs` is generated; do not edit it. After a change to `BUI_kit.h`:

```sh
dotnet tool install --global ClangSharpPInvokeGenerator --version 20.1.2
gen/generate.sh
```

Run as a dotnet tool, ClangSharp needs `libclang` and `libClangSharp` beside it: copy `runtimes/<rid>/native/*` of the `libclang.runtime.<rid>` and `libClangSharp.runtime.<rid>` 20.1.2 NuGet packages into the tool's folder. `gen/generate.rsp` holds the options; `generate.sh` adds clang's builtin headers.

# BUI for C#

Blender's widgets, layout and interaction rules from .NET, in three layers:

| Layer | Assembly | What it is |
|---|---|---|
| Interop | `Bui` (`Bui.Interop.Native`) | Every `BK_*` function, struct and constant of `kit/include/BUI_kit.h`, generated by ClangSharp. Blittable signatures only (`[assembly: DisableRuntimeMarshalling]`), callbacks as `delegate* unmanaged`. |
| Components | `Bui` | `Node`, `Frame`, `Button`, `Label`, `Context`, `Window`, `Kit`. |
| Forms | `Bui.Forms` | A Windows Forms-style API: `Form`, `Button`, `Controls.Add`, `Location`, `Size`, `Dock`, `Click`, `Application.Run`. |

Status: a first slice. Linux and macOS (GCC or Clang builds of the kit); Windows needs a MinGW build of the kit (MSVC has no exports yet).

## Build

The binding loads `libbui_kit` (a shared build of the kit) by the name `bui_kit`:

```sh
cmake -S . -B build -DBUI_BUILD_CSHARP_BINDINGS=ON
cmake --build build --target bui_kit_shared      # build/bindings/csharp/libbui_kit.so
cd bindings/csharp
dotnet run --project tests/Bui.Tests              # headless suite
dotnet run --project examples/Hello               # a window
```

The projects copy the library from `build/bindings/csharp`; pass `-p:BuiNativeDir=<dir>` for another build directory. The libraries target `net8.0`; the tests and example target `net9.0`.

## Forms

```csharp
using System.Drawing;
using Bui.Forms;

using var form = new Form { Text = "Hello from C#", Size = new Size(320, 120) };
var button = new Button { Text = "Click me", Location = new Point(110, 40), Size = new Size(100, 24) };
button.Click += (_, _) => button.Text = "Clicked";
form.Controls.Add(button);
Application.Run(form);
```

- `Location` and `Size` place a control absolutely (the kit's place manager). `Dock` other than `None` packs it against a side of its container (`Fill` takes the rest).
- Only containers (`Form`) have `Controls`.
- `Form.Context` drives a form without a window: `Configure`, `Press`, `Release`, `Motion` (tests, other hosts).

## Components

```csharp
using Bui;

var root = new Frame();
var button = new Button("Press") { Geometry = GeometryManager.Pack };
button.Click += (_, _) => System.Console.WriteLine("pressed");
root.Add(button);

using var context = new Context(root);
using var window = new Window(context, "BUI", 320, 120);
window.Show();
Window.Run();
```

`Node` takes any kit type (`new Node("slider")`) and every property by name: `Set("max", 10)`, `Set("text", "…")`, `GetNumber`, `GetString`. An unknown type or property throws `ArgumentException`. `Node.Event` delivers every kit event (`NodeEvent`: `Kind`, `A`, `B` as `BUI_kit.h` documents them).

## Ownership and threads

- A `Node` owns its native node. A parent only holds it: while a parent holds a node, the node's wrapper stays alive (the kit's retain and release hooks), so handlers keep working without a reference of your own.
- `Dispose` removes a node from its parent and frees it. A detached node that is collected is freed on the UI thread at the next input call or loop iteration.
- The kit is a UI-thread API. Call everything, `Window.Quit` included, from the thread that runs `Window.Run`.
- An exception in a handler never crosses native frames: it is held and thrown from the input call that caused it, or from `Window.Run`, which then stops.

## Regenerate the interop layer

`src/Bui/Interop/Native.g.cs` is generated; do not edit it. After a change to `BUI_kit.h`:

```sh
dotnet tool install --global ClangSharpPInvokeGenerator --version 20.1.2
gen/generate.sh
```

Run as a dotnet tool, ClangSharp needs `libclang` and `libClangSharp` beside it: copy `runtimes/<rid>/native/*` of the `libclang.runtime.<rid>` and `libClangSharp.runtime.<rid>` 20.1.2 NuGet packages into the tool's folder. `gen/generate.rsp` holds the options; `generate.sh` adds clang's builtin headers.

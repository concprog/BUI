**`bindings/csharp` gives .NET programs Blender's widget drawing, layout and interaction rules.** It has three layers: every `BK_*` function of `BUI_kit.h`, generated with no marshalling stubs; C# components (`Node`, `Button`, `Context`, `Window`); and a Windows Forms-style API on top.

It is a first slice. It runs on Linux, macOS and Windows, and installs from NuGet: `dotnet add package BlenderUI` (and `BlenderUI.Forms`), with the native kit for Linux x64, macOS arm64 and x64, and Windows x64 in the package.

## Build it

```sh
cmake -S . -B build -DBUI_BUILD_CSHARP_BINDINGS=ON
cmake --build build --target bui_kit_shared
cd bindings/csharp
dotnet run --project tests/Bui.Tests
dotnet run --project examples/Hello
```

To use a local build in your own project, see [Use BUI in your app](../in-your-app/).

## A form

```csharp
using System.Drawing;
using Bui.Forms;

using var form = new Form { Text = "Hello from C#", Size = new Size(320, 120) };
var button = new Button { Text = "Click me", Location = new Point(110, 40), Size = new Size(100, 24) };
button.Click += (_, _) => button.Text = "Clicked";
form.Controls.Add(button);
Application.Run(form);
```

`Location` and `Size` place a control absolutely, and `Dock` packs it against a side of its form. `Form.Context` drives a form without a window, for tests. [The Forms page](../forms/) lists every type and member.

## Components

```csharp
using Bui;

var root = new Frame();
var button = new Button("Press") { Geometry = GeometryManager.Pack };
button.Click += (_, _) => System.Console.WriteLine("pressed");
root.Add(button);

using var context = new Context(root);
using var window = new Window(context, "BUI", 320, 120);
window.Show();
Window.Run();
```

`new Node("slider")` makes any kit type, and `Set` / `GetNumber` / `GetString` reach every property by name. A parent keeps its children's wrappers alive, so handlers work without a reference of your own. The kit is a UI-thread API, and a handler's exception is thrown from the call that caused it.
